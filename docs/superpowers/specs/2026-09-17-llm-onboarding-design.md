# LLM onboarding for the OpenWiki repository — Design

**Date:** 2026-09-17
**Status:** approved in brainstorming (approach B)

## Goal

Make this repository easy for a coding agent (Claude Code or any AGENTS.md-aware
agent) to work *on*: build, test, change providers/prompts, write tests in the
house style, keep the generated wiki healthy, and implement the Hub without
re-deriving context every session.

Not in scope: a reusable skill for running `openwiki` on other repos, and changes
to `src/agent/prompt.ts` to improve generated wikis. Both were offered and
declined. `openwiki/` is **not** regenerated by hand or by running
`openwiki --update` as part of this work; CI (`.github/workflows/openwiki-update.yml`)
owns that.

## Decisions

- Language: English (matches README, CONTRIBUTING, `openwiki/`, upstream).
- Mechanism: Claude Code project skills in `.claude/skills/<name>/SKILL.md`
  (auto-discovered, loaded on demand) rather than `.claude/commands` / `.claude/agents`.
- `CLAUDE.md` and `AGENTS.md` stay identical to each other.
- The auto-generated "## OpenWiki" section in both files stays byte-identical so
  `openwiki --update` recognises it as current and does not rewrite it.
- No line numbers in any doc — file names and exported symbol names only, so the
  docs do not rot on every edit.
- Every claim in a skill is verified against the current source before it is
  written (commands actually run, function names actually exist).

## Deliverables

### 1. `CLAUDE.md` = `AGENTS.md` (index, ~40–60 lines)

Sections, in order:

1. Existing `## OpenWiki` block — unchanged.
2. `## Commands` — `pnpm install`, `build`, `dev`, `test`, `typecheck`,
   `lint`/`lint:check`, `format`/`format:check`, `coverage`. One line each.
3. `## Conventions` — one PR = one change; Conventional Commits titles; ESM
   (`"type": "module"`, `.ts` imports in tests); Node ≥ 20; Ink/React for the
   TUI; Vitest; Prettier + ESLint gate CI; agents must surface scope
   violations (from CONTRIBUTING).
4. `## Where things live` — 8–10 bullets mapping concerns to files
   (CLI parsing → `src/commands.ts`, TUI/run lifecycle → `src/cli.tsx`,
   providers → `src/constants.ts`, model creation → `src/agent/index.ts`, …).
   Points to `docs/source-map.md` for detail.
5. `## Skills` — list of the six skills with one-line "use when".
6. `## Hub work` — pointer to spec and plan under `docs/superpowers/`.

### 2. `.claude/skills/` — six skills

Each skill: YAML frontmatter (`name`, `description` phrased as "Use when …"),
then a short body. Bodies stay under ~120 lines; anything longer moves to a
`reference.md` beside `SKILL.md`.

| Skill | Purpose | Body outline |
|---|---|---|
| `openwiki-dev-loop` | Build, test, run the CLI locally, pre-PR gate | Install/build; running `pnpm dev` vs `dist/cli.js`; running against another repo (`pnpm link --global`, `OPENWIKI_DEV=1 openwiki --dry-run`, `-p`); what `OPENWIKI_DEV=1` unlocks (`--dry-run` execution-plan view, no credentials read, no agent, no writes); pre-PR checklist (`format`, `lint`, `typecheck`, `test`); where `~/.openwiki/.env` lives and how to avoid touching the real one during tests. |
| `add-model-provider` | Cross-file checklist for a new provider | Ordered steps: `OpenWikiProvider` type + `PROVIDER_CONFIGS` in `src/constants.ts` (`requiresBaseUrl` semantics); model-creation branch in `src/agent/index.ts`; `managedEnvKeys` in `src/env.ts`; onboarding step in `src/credentials.tsx`; README provider list/table; `test/constants.test.ts` + `test/env.test.ts`; `openwiki/cli/usage.md` table only if CI wiki update is not expected soon. Includes a "done when" list. |
| `change-agent-prompt` | Safely edit `src/agent/prompt.ts` | How the system prompt is assembled (`RunContext`, git evidence from `src/agent/utils.ts`, init vs update instructions, AGENTS/CLAUDE insertion rules); which prompt sections are contractual with the update-noop logic and `.last-update.json`; how to validate without an LLM call: import `createSystemPrompt` / `createModeInstructions` / `createUserPrompt` from a Vitest test (or `tsx -e`) and inspect the output; `--dry-run` only shows the execution plan, not the prompt; then one `-p` run on a small repo; what to add to `test/` when behaviour changes. |
| `write-tests` | Vitest patterns used here | File naming; importing `.ts` sources directly; tmp git repos via `mkdtemp` + `execFile("git")` (pattern from `test/update-noop.test.ts`); env isolation for `src/env.ts` tests; redaction tests for secrets; what not to mock; running a single file (`pnpm vitest run test/x.test.ts`). |
| `maintain-wiki` | Rules for the generated `openwiki/` dir | It is generated output, owned by CI; when hand-edits are acceptable (never for structure, small factual fixes only); `.last-update.json` semantics and the noop check; the AGENTS/CLAUDE "## OpenWiki" section contract; how to regenerate locally if explicitly asked (`openwiki --update` in repo root, needs key). |
| `hub-implementation` | Entry point for Hub work | Links to `docs/superpowers/specs/2026-07-08-openwiki-hub-design.md` and `plans/2026-07-08-openwiki-hub.md`; hard constraints (root CLI untouched except `exports` in `package.json`; `hub/server` + `hub/web` in the pnpm workspace; German UI; no auth; no push-back to repos); reminder to follow the plan's task order and keep upstream-merge friction low. |

### 3. `docs/source-map.md`

One section per source file under `src/` and `test/`. For each: one-sentence
responsibility, the exported symbols worth knowing (name + one clause),
and "read this when …". Large files (`src/cli.tsx`, `src/agent/index.ts`,
`src/credentials.tsx`) additionally get an internal outline listing their
top-level components/functions in order so an agent can `Grep` for a name
instead of reading the whole file. No line numbers.

## Verification

- `pnpm run format:check` passes (Prettier covers `.md` unless ignored — check
  `.prettierignore`; if `.claude/` or `docs/` are formatted, run `pnpm run format`).
- Every command listed in a skill was executed once during implementation
  (`build`, `test`, `typecheck`, `lint:check`, `dev --help`, `--dry-run`).
- Every symbol named in `docs/source-map.md` and the skills exists in the
  current source (`Grep` check before finishing).
- `CLAUDE.md` and `AGENTS.md` are byte-identical (`git diff --no-index`).
- Skills show up when listed by Claude Code in this project.

## Out of scope (deliberate)

- Running `openwiki --update` or editing `openwiki/*.md` content.
- Any change under `src/` or `test/`.
- Custom subagents (`.claude/agents`) or slash commands (`.claude/commands`).
- A release/publishing skill — this fork does not publish to npm.
